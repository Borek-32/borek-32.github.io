Executive summary

what was built

Problem

Implement and inspect a staged MFCC-based recognition path in FPGA logic while keeping controller sequencing, fixed-point data, and debug output testable.

Implementation

A controller advances through ready/start handshakes for ADC, WINDOW, FFT, MEL, LOGMEL, DCT, COMP, and optional DEBUG states.

Result

The polished copy and verification directory are mapped. This page records how evidence is produced without claiming a final measured recognition result that has not yet been published.

Implementation flow

processing path
  1. Capture a frame.The controller starts ADC, watches busy/done status, and hands captured samples toward the feature path.
  2. Window and transform.WINDOW prepares the frame and FFT converts it to the frequency domain.
  3. Build mel features.MEL and LOGMEL reduce the spectrum into log-scaled perceptual bands.
  4. Decorrelate and compare.DCT produces cepstral coefficients; COMP uses the result to update digit/record state.
  5. Expose debug state.SW1 controls optional UART packet generation after COMP, and LD1 mirrors whether debug is enabled.
