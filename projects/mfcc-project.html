FPGA MFCC spoken-digit recognizer

A complete fixed-point speech pipeline for Basys 3: microphone capture, overlapped windowing, a Xilinx FFT, MEL and LOGMEL features, DCT coefficients, and a hardware SAD/L1 template comparator. The evidence below comes from the 107-page project report and is presented with the limits of the retained dataset kept explicit.

Executive summary

what was built

Problem

Run an explainable spoken-digit feature and comparison chain in FPGA logic while keeping fixed-point arithmetic, memory addressing, and controller sequencing observable.

Implementation

A 16,384-sample acquisition becomes 63 overlapped frames, 32 MEL bands, eight non-DC DCT coefficients, and a 16-frame template compared against 30 stored references.

Result boundary

The integrated design is routed and the retained 30-record collection separates 30/30 in leave-one-out analysis. That is development-set evidence, not population-wide speaker accuracy.

Implemented architecture

data reduction path

Feature dimensions

The ADC stores 16,384 samples. Hann-windowed 512-sample frames advance with a 256-sample hop, producing 63 frames. The pipeline retains 256 FFT magnitude bins, 32 MEL and LOGMEL values, and eight non-DC DCT coefficients per frame.

Comparison convention

The comparator selects a 16-frame activity window and evaluates SAD/L1 distance over 16 × 8 coefficients against 30 references: ten digits with three retained trials per digit.

  1. Acquire once.The ADC path fills the 16,384-sample record, including preroll handling and zero padding.
  2. Frame and taper.WINDOW reads 63 overlapping 512-sample regions and applies fixed-point Hann coefficients.
  3. Transform.A 512-point FFT wrapper stores 256 magnitude values using the corrected sample and output-address contracts.
  4. Build perceptual bands.MEL reduces the spectrum to 32 filters; LOGMEL applies the fixed-point logarithmic approximation.
  5. Compact spectral shape.DCT writes eight signed non-DC coefficients while MEL energy remains available for onset selection.
  6. Record or compare.COMP can write a reference or evaluate all 30 stored references under the 16-frame × 8-coefficient SAD/L1 rule.
  7. Expose internal state.The optional UART DEBUG packet serializes 1,362 words per frame without burdening normal operation.

Implementation scale: the placed design uses 5,559 LUTs, 8,412 registers, 23.5 block-RAM tiles, and 15 DSPs. The timing result covers the internal 100 MHz constraint; external board-interface timing is not characterized here.

Retained-dataset evaluation

30 archived utterances

The retained collection contains digits 0–9 with three FPGA-UART recordings per digit. Each record includes the complete ADC array and all downstream stage memories. In leave-one-out comparison, every query selected the correct digit under the implemented 16-frame × 8-coefficient SAD/L1 convention.

How to read 30/30: this is leave-one-out separability inside one small retained development collection with three trials per digit and no broad speaker or noise stratification. It is not a claim of 100% live-speaker or population-wide accuracy.

Microphone front end and PCB

design to physical build

The project includes an LM324 microphone amplifier, buffered reference, adjustable gain, and two unequal Sallen-Key low-pass sections. The circuit was converted into a 44 mm × 40 mm single-sided through-hole board for home fabrication.

Known limitations and next proof

honest status

Known limitations

  • The 30-record collection is historical development evidence, not a broad accuracy study.
  • Runtime reference recording and flush are implemented but lack retained direct readback proof.
  • External SPI and board-interface timing is not characterized by the internal timing result.
  • The analog response lacks a calibrated physical transfer-function sweep.

Best next evidence

  • Record one known digit, read the selected reference slot back, then recall it.
  • Capture reference memory before and after flush.
  • Run a labeled live spoken-digit comparison and retain the full frame sequence plus final display/UART result.
  • Measure the physical front-end response with calibrated equipment.
