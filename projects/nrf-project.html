nRF24L01: transmitter, receiver, and debug builds

A Basys3 workspace for nRF24L01 communication over SPI. Separate transmitter, receiver, and troubleshooting builds expose radio configuration and register state instead of treating the module as an opaque peripheral.

Executive summary

what was built

Problem

Bring up an nRF24L01 from FPGA logic while making SPI transactions, configuration registers, payload state, and failure signals inspectable on the board.

Implementation

Reusable helpers separate register writes, payload reads/writes, one-byte commands, clock division, debounce, and seven-segment display logic.

Result

The workspace records four focused builds and their common mapping. A complete published over-the-air TX/RX proof path is still the next verification target.

Implementation flow

four build roles
  1. Original transmitter.nrfTX initializes registers, writes a 32-byte payload, issues commands, pulses CE, and exposes switch input on LEDs.
  2. Original receiver.nrfRX configures receive mode, waits for IRQ, reads payload data, clears status, and returns to listening.
  3. TX troubleshooting.The debug build adds register readback, display stepping, and maximum-retry visibility.
  4. RX troubleshooting.The receive debug path centers on IRQ, payload read, FIFO/IRQ clearing, and visible register state.
  5. Shared board mapping.SPI and radio-control signals are mapped to Basys3 PMOD JC across the documented builds.

Known limitations and next proof

honest status

Known limitation

The documentation maps TX, RX, and register-debug paths, but does not yet publish one continuous, independently inspectable over-the-air transfer from transmitter input to receiver output.

Best next evidence

Publish a wiring photo, register readback capture, configuration table, and short test showing the selected transmitter payload arriving at the receiver output.
